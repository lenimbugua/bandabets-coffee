# Critical CSS via Beasties Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate the last big PSI insight — the 34.1 KiB / ~480 ms render-blocking `entry.css` — by inlining a build-generated critical-CSS subset and deferring the full stylesheet, targeting ≤10 KB gzip of inline critical CSS and zero render-blocking external stylesheets on first paint.

**Architecture:** A script (`scripts/extract-critical-css.mjs`) runs Beasties (the Nuxt-maintained critters fork, devDependency) over the SSR HTML of a representative route set against the built `entry.css`, unions and dedupes the critical rules, and writes a **committed artifact** `server/assets/critical.css`. At runtime, a Nitro plugin (`server/plugins/critical-css.js`) hooks `render:html`: it reads the artifact once (Nitro server-assets storage), injects it as an inline `<style data-critical>`, and rewrites the `entry.*.css` `<link rel="stylesheet">` to the same `media="print"` + onload swap + `<noscript>` pattern already used for `noncritical.css`. A stale artifact self-heals: anything missing from the inline subset is styled ~0.5 s later when the full (deferred) sheet arrives, so regeneration is a maintenance step, not a correctness requirement. No Vercel build-command change (infra untouched); the artifact ships inside the server bundle because `server/assets/` is bundled by Nitro automatically.

**Tech Stack:** beasties 0.4.3 (devDependency), Nitro `render:html` hook + `useStorage("assets:server")`, existing Lighthouse harness.

**Spec:** in-chat design approved 2026-08-31 ("proceed" on the beasties round); committed-artifact approach chosen by the controller (per-request extraction too slow; build-command changes are the infra team's territory).

### Task 2: Nitro plugin — inline critical, defer the entry stylesheet

**Files:**
- Create: `server/plugins/critical-css.js`

**Interfaces:**
- Consumes: `server/assets/critical.css` from Task 1 (via `useStorage("assets:server")`).
- Produces: modified SSR head for every HTML render in production.

- [ ] **Step 1: Write the plugin**

```js
// Inlines the committed critical-CSS artifact (server/assets/critical.css,
// generated by scripts/extract-critical-css.mjs) and defers the full entry
// stylesheet with the same media="print" swap used for noncritical.css.
// A stale artifact self-heals: anything it misses is styled when the full
// sheet arrives (~0.5 s on Slow 4G). No-op in dev, when the artifact is
// missing, or on any internal error — this plugin must never break a render.
export default defineNitroPlugin((nitroApp) => {
  if (import.meta.dev) return;

  let criticalPromise = null;
  const loadCritical = () =>
    (criticalPromise ??= useStorage("assets:server")
      .getItem("critical.css")
      .then((raw) => {
        const css = typeof raw === "string" ? raw : raw ? raw.toString() : "";
        return css.trim().length > 0 ? css : null;
      })
      .catch(() => null));

  const ENTRY_LINK_RE =
    /<link rel="stylesheet"[^>]*href="(\/_nuxt\/entry\.[^"]+\.css)"[^>]*>/;

  nitroApp.hooks.hook("render:html", async (html) => {
    try {
      const critical = await loadCritical();
      if (!critical) return;
      for (let i = 0; i < html.head.length; i++) {
        const match = html.head[i].match(ENTRY_LINK_RE);
        if (!match) continue;
        const href = match[1];
        html.head[i] = html.head[i].replace(
          ENTRY_LINK_RE,
          `<style data-critical>${critical}</style>` +
            `<link rel="stylesheet" href="${href}" media="print" onload="this.media='all'" crossorigin>` +
            `<noscript><link rel="stylesheet" href="${href}" crossorigin></noscript>`
        );
        return; // exactly one entry stylesheet
      }
    } catch {
      // degrade to the untouched head
    }
  });
});
```

Adapt mechanically if reality differs (e.g. the link renders without `crossorigin`, or `html.head` entries batch multiple tags per string — the regex/replace already handles a link embedded in a longer string; verify against actual output and keep the entry link's other attributes if any). The critical CSS must not need HTML-escaping (CSS containing `</style>` would break out — assert in Task 1's script that the artifact contains no `</style` substring; add that assertion if missing).

### Regeneration workflow

When `app/assets/css/style.css` or the DOM structure of the extraction route set (`/`, `/promotions`, `/share-bets`, `/login`, `/leagues`) changes materially:

```bash
pnpm build && pnpm critical:extract
```

then `git add server/assets/critical.css` and commit if the diff is non-trivial. A **stale** artifact self-heals: anything the inline subset misses is still styled correctly ~0.5 s later when the deferred full `entry.*.css` sheet swaps in via the `media="print"` → `onload` → `media="all"` pattern — regeneration is a maintenance/perf-quality step (keeping the FCP win current as the design system evolves), not a correctness requirement. The extraction script fails loudly (exit 1) if a future regeneration pushes the union past 15 KB gzip, which should be read as "the route set or Beasties config needs revisiting," not "raise the ceiling."
